# SpinScreen: прошивка экрана и мотора для CAL-принтера SpinSlicer

**Русский** · [English](README.en.md)

Одно железо: плата **ESP32-S3 Super Mini**, экран **ST7789 2.4" 240×320** (например GMT024-08-SPI8P)
и джойстик **KY-023** на проводах, драйвер мотора **TMC2209**, с Raspberry Pi **USB-кабелем**. Всё это
задано в `config.h`, на плате настраивать нечего: прошил, и экран работает. Чёрный фон, розовый интерфейс,
плавные анимации, логотип SpinSlicer при загрузке, большая карточка «Печать» сверху на главной, меню на
русском и английском. Аксолотль Spinny по желанию.

**Меню:**
- **Строка готовности** внизу главной: «Готов к печати» или первое, чего не хватает (Raspberry не
  подключена, на ней старый SpinPi, проектор не подключён), и «Есть обновление 0.8.x», если проверка
  его нашла. Когда места хватает, справа ещё точки «Raspberry» и «Проектор».
- **Печать** → список видео (с флешки в Raspberry и загруженные по сети) → подготовка: **обороты** (из расчёта
  SpinSlicer), **поправка экспозиции**, пауза до света + розовая кнопка **ПЕЧАТЬ** → разгон / прогрев /
  пауза → экран печати (время, оборот k из N, синхронизация) → «Готово!» + «Недосвет / Норма / Пересвет».
  Для `.spin` с превью внутри кольца прогресса рисуется **силуэт детали**: тёмный, пока свет не
  включился, потом разгорается вместе с дозой; точка на внутреннем круге крутится с флаконом.
- **Печатать?** Печать, отправленная из SpinSlicer, сама не начинается: экран показывает, что пришло
  (имя, обороты, время), и ждёт. Вправо = печатать, влево = отменить.
- **Подключение**: QR-код страницы принтера.
- **Мастер настройки** (первая строка Настроек; сам открывается при первом включении новой платы),
  10 шагов с полосой прогресса: язык → связь (Raspberry, проектор по HDMI, сеть: что подключено,
  а что нет) → резкость (↑↓ мишень / сетка / круг) → центровка → ширина флакона (это число нужно в
  SpinSlicer) → направление (флакон крутится, ↑↓ меняет сторону) → ровно 1 оборот (по отметке видно,
  верна ли передача; ↑ повторить) → скорость печати (↑↓, вживую) → яркость → итог: что настроено.
  «←» на первом шаге пропускает мастер.
- **Настройки**: Мастер настройки, Мотор, Проектор, Экран, Система, каждая отдельной страницей
  (строки «Назад» нет: влево или долгое нажатие):
  - Мотор: проверка вращения, скорость, направление, разгон, микрошаг, шагов на оборот, передача,
    «ровно 1 оборот», обнуление угла (слева живой тахометр). Изменения во время вращения применяются
    после остановки.
  - Экран: яркость, язык, тёмный экран при печати, **Засыпать** (подсветка гаснет после 1 / 5 / 15 / 30 минут
    без дела, по умолчанию 5; первое касание джойстика только будит; печать, «Печатать?» и сообщения будят сами); **Главная**: Карточка (по умолчанию: «Печать» большой
    карточкой сверху) или Аксолотль (Spinny сбоку); **Окраска** аксолотля: розовый, золотой, дикий, чёрный, голубой, радуга RGB.
  - Проектор: Чёрный, Белый, Сетка, Фокус, Круг, Центровка, Ширина флакона.
  - Система: сразу всё о принтере: версия прошивки, Raspberry (связь, температура), сеть (IP, Wi-Fi),
    свободное место (SD, флешка), сколько напечатано, часы проектора, плата (время работы, к/с).
    Кнопки: **Проверить обновления** (потом **Обновить до …**, см. ниже), **Обновить прошивку** (только
    если на флешке есть подходящая), перезагрузить или выключить Raspberry (всё с подтверждением).

**Обновления по воздуху.** Настройки → Система → **Проверить обновления**: Raspberry спрашивает GitHub о
последнем релизе. Если он новее программы на Raspberry или прошивки платы, кнопка становится
**Обновить до 0.8.x**. Нажал, подтвердил: сначала Raspberry записывает плате прошивку релиза (`esptool`),
потом обновляет сама себя (`get.sh` релиза, 2–5 минут, без перезагрузки) и говорит на экране, как прошло.
Во время печати не обновляется.

**Пины хранятся на плате** (`board.h`). Своя сборка (Arduino IDE, arduino-cli) берёт пины из `config.h`
и записывает их в память платы. Сборка релиза (её делает GitHub с `-DSPIN_RELEASE=1`) берёт пины,
которые плата уже записала, поэтому релиз по воздуху встаёт и на плату с другой проводкой, а пины
остаются её. Новая плата, у которой в памяти ещё ничего нет, берёт пины релиза. Пишется только сама
программа (с адреса 0x10000): настройки и пины в памяти платы не стираются. Поменял проводку: поправь
`config.h` и прошей свою сборку с компьютера.

**Прошивка с флешки.** `spinscreen*.bin` в корне флешки (своя сборка) Raspberry предлагает кнопкой
**Обновить прошивку**, если она подходит плате: собрана для тех же пинов (строка `SPINPINS …`) или это
сборка релиза. Первая прошивка с этими кнопками (0.8.5) ставится с компьютера, как раньше.

**Джойстик:** вверх / вниз = по списку (держишь — листает), вправо или нажать = OK, влево или долго
нажать = назад. На экране печати одно «←» только спрашивает («← ещё раз — стоп»), остановит второе «←»
в течение 3 секунд: случайный толчок ручки или наводка от мотора на провода печать не прервут.
Центр джойстика запоминается при включении, в этот момент ручку не трогать.

**Мотор:** шаги идут от аппаратного таймера 10 МГц с дробным накоплением периода, поэтому
средняя скорость точная и каждый шаг посчитан. Raspberry спрашивает угол (`POS`) и держит видео в синхроне.

- `SpinScreen/`: прошивка, открывается в Arduino IDE (`SpinScreen.ino`)
- `SpinScreen/config.h`: пины и железо (единственный вариант), значения мотора по умолчанию
- `screens/`: **скриншоты всех экранов** (их рисует настоящий интерфейс: `sim/shots.cpp` + `dev/make_shots.py`)
- `tools/pi_test.py`: притвориться Raspberry Pi с компьютера и проверить связь
- `sim/`: интерфейс на ПК. `make virtual_esp`: **виртуальный ESP32** в окне (настоящий интерфейс,
  джойстик с клавиатуры, мотор, связь с SpinPi через виртуальный USB-порт); `sim` и `bench`: запись кадров и замер скорости
- `SpinScreen/qrcodegen.*`: QR-коды, библиотека Project Nayuki (MIT)
- `gen/make_fonts.py`: генератор шрифтов с кириллицей из шрифта [Onest](https://fonts.google.com/specimen/Onest) (лицензия SIL OFL): `python gen/make_fonts.py Onest[wght].ttf SpinScreen/fonts.h`

## Подключение

| Экран ST7789 2.4" | ESP32-S3 |
|---|---|
| GND | GND |
| VCC | **3V3** (не 5V) |
| SCL | 43 (TX) |
| SDA | 44 (RX) |
| RES | 1 |
| DC | 2 |
| CS | 3 |
| BLK | 4 |

| Джойстик KY-023 | ESP32-S3 |
|---|---|
| GND | GND |
| +5V | **3V3** (не 5V: иначе на входы ESP придёт больше 3,3 В) |
| VRx | 13 |
| VRy | 11 |
| SW | 12 |

Драйвер мотора TMC2209: STEP → 5, DIR → 6, EN → 7, плюс общий GND с ESP32; мотор от своего блока 12–24 В.

С Raspberry Pi: USB-кабель с данными (USB-C платы в любой USB-порт Raspberry).

Направления джойстика перепутаны? В `config.h`: `JOY_SWAP_XY`, `JOY_INVERT_Y`, `JOY_INVERT_X`.
Команда `JOY` по USB покажет, что видит плата.

## Прошить

**Проще всего — из браузера** (Windows, Mac, Linux): https://v0xeii.github.io/SpinPrinter/flasher/ в Chrome или Edge.

**Одной командой** (плата подключена к компьютеру USB-кабелем, Arduino IDE 2 с ядром esp32 установлен):
```
bash SpinScreen_v0.7/tools/flash.sh
```
Или через Arduino IDE:

1. Arduino IDE 2 → Boards Manager → найти **esp32** (от Espressif) → Install.
2. Tools → Board → **ESP32S3 Dev Module**.
3. Tools → **USB CDC On Boot: Enabled**.
4. Открыть `SpinScreen/SpinScreen.ino`, нажать Upload.
5. Если плата не находится: зажать BOOT, нажать и отпустить RESET, отпустить BOOT, снова Upload.

## Если экран странный

Всё это правится в `config.h` и новой прошивкой:
- Ничего нет / белый: провода экрана, подсветка BLK, питание 3V3.
- Цвета как негатив: `TFT_INVERT 0`.
- Красный и синий перепутаны: `TFT_BGR 1`.
- Вверх ногами: `TFT_ROTATION 3`.
- Мусор или полосы на длинных проводах: `TFT_SPI_MHZ 20`.

## Нагрузка на ESP32 и плавность

Интерфейс держит **ровные 60 кадров в секунду**: кадры идут по точной сетке в микросекундах,
и анимации считаются от времени кадра, а не от «когда получилось». Поэтому нет рывков от того,
что один кадр 16 мс, а другой 17. На 30 к/с экран переходит, только если всё полностью замерло
(никто не нажимает, Spinny спит или выключен). Если плата не успевает рисовать 60, она сама
переходит на ровные 30, а не дёргается между 60 и 30.

Что сделано, чтобы кадр был дешёвым:
- На ESP32-S3 `sqrtf`, `fminf`, `fmaxf` и деление — это вызовы библиотеки (около 100 тактов на
  корень). В рисовании их заменили на встроенные быстрые версии с точностью ~5·10⁻⁶.
- Фигуры рисуются «шагами по строке»: если пиксель далеко от края, сразу перескакиваем через
  несколько пикселей (пустые пропускаются, внутренние просто заливаются). Считаются только
  пиксели на краю, где нужно сглаживание.
- Тело Spinny рисуется как одна фигура, а не 14 отдельных кусков друг на друге: каждый пиксель
  считается один раз и только по 1–3 ближайшим кускам. Тонкие волоски жабр рисуются линиями.
- Свечение считается кольцами по строкам, без вычислений на каждый пиксель.
- Файл рисования компилируется с `-O2` (Arduino по умолчанию собирает `-Os`, для маленького кода).
- На экран уходит только то, что изменилось. Байты переставляются по пути в маленький буфер,
  поэтому следующий кадр можно рисовать, пока предыдущий ещё уходит по DMA.

**Сколько это стоит.** Замер в эмуляторе ESP32-S3 (QEMU от Espressif), считались команды
процессора на кадр:

| | v0.6 | v0.7 |
|---|---|---|
| меню, Spinny плавает | ~9,7 млн | ~1,7 млн |
| меню, листаем | ~11,9 млн | ~1,9 млн |

Примерно в 6 раз меньше работы. На настоящей плате при 240 МГц это ориентировочно 7–12 мс на
кадр (бюджет для 60 к/с — 16,7 мс). Эмулятор не считает такты точно, поэтому настоящее время
кадра смотри на своей плате: Настройки → Система, строка «Экран» (кадры в секунду, мс на кадр).

Мотор от экрана не зависит: шаги идут от аппаратного таймера.

## Spinny

Spinny — гибкая цепочка из 15 суставов: голова плывёт к цели, тело тянется следом. Поэтому
он изгибается, а разворачивается через себя, лицом к тебе (видно оба глаза). На скорости он
прижимает лапки, а когда стоит, гребёт ими. Жабры «дышат» и шевелятся.

- Плавает по своему уголку: то несколько гребков на месте, то разворот и через весь уголок.
  Тело всегда остаётся на экране.
- Держится рядом с выбранным пунктом и ныряет, когда листаешь.
- Если ничего не нажимать: иногда всплывает глотнуть воздуха, иногда ему насыпают корм. Он
  подплывает и глотает (открывает рот).
- Через минуту без нажатий медленно опускается ровно на дно и засыпает (zZz).
- «Готово!»: радостно носится туда-обратно. Ошибка: пугается и шарахается в сторону.
- Выключить или перекрасить: Настройки → Главная / Окраска.

## Протокол с Raspberry Pi (USB, 115200, строки текста)

| Raspberry → ESP | что делает |
|---|---|
| `PING` | ответ `PONG SpinScreen 0.8.7`; Raspberry шлёт раз в секунду, иначе экран пишет «нет Raspberry» |
| `RPM 9.5` | скорость вращения, об/мин |
| `SPIN 1` / `SPIN 0` | мотор вкл/выкл (с плавным разгоном) |
| `STATE PRINT` / `STATE DONE` / `STATE IDLE` / `STATE ERROR текст` | состояние печати |
| `PROG 42 80` | прогресс 42 %, осталось 80 секунд |
| `MSG текст` | Spinny скажет это в пузыре |
| `STATS` | для настройки: ответ `STATS <к/с> fps <работа> ms <КБ> KB draw <отрисовка> ms scr <экран> page <страница> sel <пункт>` |
| `KEY u` / `d` / `o` / `b` | нажать кнопку вверх / вниз / OK / назад (тесты с компьютера) |
| `GET` | текущие настройки |
| `POS` | ответ `POS <угол°> <об/мин> <на скорости 0/1>`, отвечает за ~1 мс |
| `ZERO` | угол := 0 (ответ `ZEROED`) |
| `SETANGLE 12.5` | угол := 12.5° (Raspberry совмещает флакон с кадром видео в момент включения света) |
| `TURNS 6` · `WAIT 30 warm` · `DROPS 2` | сколько оборотов · ожидание до света (spin/warm/dark) · пропуски кадров |
| `URL http://…` / `HOST …` / `NET …` | адрес для QR-кода, имя хоста, Wi-Fi |
| `ASK обороты секунды имя` · `ASK END` | печать из SpinSlicer ждёт «да» на экране · вопрос снят (истёк или заменён) |
| `FILE имя.mp4` / `SYNC 12` | что печатается / ошибка синхронизации в мс (для экрана) |
| `FL BEGIN n поправка% пауза обороты` · `FL i rpm usb расчёт допуск сек/об кадры_ок имя` · `FL END` | список видео для экрана «Печать» |
| `CAL offset vial` | центровка и ширина флакона (для меню Проектор) |
| `JOY` | что видит джойстик (проверка проводов) |
| `PINS` | ответ `SPINPINS 43,44,… nvs` (пины в работе; `nvs` = плата хранит их у себя) и `SPINBUILD release/local` |
| `SYS ip=… wifi=% temp=°C sd=ГБ usb=ГБ prints=n proj=ч hdmi=1/0` | для страницы Система и мастера, раз в 10 с; `-` = неизвестно. Нет этой строки 15 с при связи: на Raspberry старый SpinPi (так и пишет экран) |
| `FW версия usb/release` · `FW -` | Raspberry может поставить эту прошивку · нечего ставить |
| `SHAPE BEGIN 56 56` · `SHAPE y hex` · `SHAPE END` · `SHAPE -` | силуэт детали для экрана печати (1 бит на точку, по 8 строк в строке протокола) · силуэта нет |
| `FWUP` · `FWUP END` | Raspberry начала писать прошивку (экран «Обновляю прошивку…») · закончила |
| `UPD CHECKING` · `UPD STEP текст` · `UPD NONE` · `UPD AVAIL 0.9.0` · `UPD ERR текст` | ответ на «Проверить обновления»: пока идёт проверка, в строке крутится значок, а `STEP` пишет, что делается |
| `UPD RUN pi` · `UPD IDLE` | Raspberry обновляет себя (экран «Обновляю Raspberry…») · новый SpinPi запустился |

При включении плата пишет `READY SpinScreen 0.8.7 st7789_240x320 320x240 joystick` (и `noscreen`, если экран не запустился).

| ESP → Raspberry | когда |
|---|---|
| `EV LIST` | открыли список видео |
| `EV PRINT i обороты поправка% пауза` | нажали ПЕЧАТЬ |
| `EV RESULT under/ok/over` | ответ на «Как получилось?» |
| `EV PATTERN name` · `EV OFFSET px` · `EV VIALW px` | Настройки → Проектор |
| `EV REBOOT` / `EV POWEROFF` · `EV FWUPDATE` · `EV UPDCHECK` · `EV UPDATE` | Настройки → Система |
| `EV STOP` | на экране печати дважды «←» за 3 секунды |
| `EV GO` / `EV NO` | ответ на «Печатать?» |
| `EV SPIN 1/0`, `EV RPM 9.5` | поменяли мотор или скорость с экрана |
