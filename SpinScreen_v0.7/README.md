# SpinScreen: прошивка экрана и мотора для CAL-принтера SpinSlicer

**Русский** · [English](README.en.md)

Плата **ESP32-S3 Super Mini**, экран **ST7789 1.9" 170×320** или **1.3"/1.54" 240×240**. Чёрный фон, розовый интерфейс,
плавные анимации, аксолотль Spinny (плавает сбоку), меню на русском и английском.

**Меню:**
- **Печать** → список видео (с флешки в Pi и загруженные по Wi-Fi) → подготовка: **обороты** (из расчёта
  SpinSlicer), **поправка экспозиции**, пауза до света + розовая кнопка **ПЕЧАТЬ** → разгон / прогрев /
  пауза → экран печати (время, оборот k из N, синхронизация) → «Готово!» + «Недосвет / Норма / Пересвет».
- **Подключение**: QR-код страницы принтера.
- **Сервис**:
  - Проектор: Чёрный, Белый, Сетка, Фокус, Круг, Центровка, Ширина флакона.
  - Мотор: проверка вращения, скорость, направление, разгон, микрошаг, шагов на оборот, передача,
    «ровно 1 оборот», обнуление угла; слева живой тахометр.
  - Экран: яркость, язык, тёмный экран при печати.
  - Аксолотль: показывать или нет (без него меню на весь экран), окраска: розовый, золотой, дикий,
    чёрный, голубой, радуга RGB.
  - Raspberry Pi: перезагрузить или выключить (с подтверждением).
  - О принтере.

**Мотор:** шаги идут от аппаратного таймера 10 МГц с дробным накоплением периода, поэтому
средняя скорость точная и каждый шаг посчитан. Pi спрашивает угол (`POS`) и держит видео в синхроне.

- `SpinScreen/`: прошивка, открывается в Arduino IDE (`SpinScreen.ino`)
- `SpinScreen/config.h`: **все пины и настройки в одном месте**
- `tools/pi_test.py`: притвориться Raspberry Pi с компьютера и проверить связь
- `sim/`: интерфейс на ПК. `make virtual_esp`: **виртуальный ESP32** в окне (настоящий интерфейс,
  кнопки, мотор, связь с SpinPi через виртуальный USB-порт); `sim` и `bench`: запись кадров и замер скорости
- `SpinScreen/qrcodegen.*`: QR-коды, библиотека Project Nayuki (MIT)
- `gen/make_fonts.py`: генератор шрифтов с кириллицей из шрифта [Onest](https://fonts.google.com/specimen/Onest) (лицензия SIL OFL): `python gen/make_fonts.py Onest[wght].ttf SpinScreen/fonts.h`

## Что нового в 0.7.2

- **Pi можно подключить проводами:** RX (GPIO44) ← Pi пин 8, TX (GPIO43) → Pi пин 10, GND, 5V.
  USB-кабель тоже работает, одновременно: прошивка отвечает туда, откуда пришёл PING от Pi.
  Мусор с неподключённого провода отбрасывается (вход подтянут вверх, строки с управляющими байтами не принимаются).

## Что нового в 0.7.1

- **Spinny больше не вылезает в меню.** Его уголок (122 пикселя) короче двух его тел, и на
  развороте у края хвост заезжал в список. Теперь тело упирается в стенку уголка и
  поворачивается к тебе, как настоящий аксолотль у стенки аквариума.
- **Spinny больше не дёргается туда-обратно.** Если корм, место для сна или цель оказывались
  посередине уголка, он каждый кадр заново решал, в какую сторону плыть, и разворачивался без
  конца. Теперь сторона выбирается с запасом, а маленький шаг назад он делает лапками, без разворота.
- **Экран больше не подвисает из-за USB.** Если ESP подключена к компьютеру, а порт никто не
  читает, каждая строка в USB ждала примерно 100 мс, и интерфейс замирал. Теперь строки уходят
  через отдельную задачу, а интерфейс никогда не ждёт.
- Проверка: `sim/spinny_stress.cpp` гоняет настоящий интерфейс 20 минут с лагами, 30/60 к/с,
  нажатиями, печатью и ошибками. Было: 4–14 тысяч кадров, когда Spinny вне уголка, и 30–45
  серий разворотов туда-обратно. Стало: 0–3 кадра (только когда он заплывает на заставке) и 0–2 серии.

## Подключение

| Экран | ESP32-S3 |
|---|---|
| GND | GND |
| VCC | **3V3** (не 5V) |
| SCL | 12 |
| SDA | 11 |
| RES | 8 |
| DC | 9 |
| CS | 10 |
| BLK | 7 |

Кнопки (одна нога на пин, вторая на GND, резисторы не нужны): ВВЕРХ → 4, ВНИЗ → 5, OK → 6.
Долгое нажатие OK = назад/стоп. Вместо кнопок можно крутилку KY-040: CLK → 4, DT → 5, SW → 6,
и в `config.h` поставить `INPUT_MODE INPUT_ENCODER`.

Драйвер мотора (потом): STEP → 1, DIR → 2, EN → 13, плюс общий GND с ESP32.

## Прошить

**Проще всего — из браузера** (Windows, Mac, Linux): https://v0xeii.github.io/SpinPrinter/flasher/ в Chrome или Edge.

**Одной командой** (плата подключена к компьютеру USB-кабелем, Arduino IDE 2 с ядром esp32 установлен):
```
bash SpinScreen_v0.7/tools/flash.sh
```
Или через Arduino IDE:

1. Arduino IDE 2 → Boards Manager → найти **esp32** (от Espressif) → Install.
2. Tools → Board → **ESP32S3 Dev Module**.
3. Tools → **USB CDC On Boot: Enabled**.
4. Открыть `SpinScreen/SpinScreen.ino`, нажать Upload.
5. Если плата не находится: зажать BOOT, нажать и отпустить RESET, отпустить BOOT, снова Upload.

## Какой экран

В `config.h` одна строка: `#define TFT_PANEL PANEL_170x320` (1.9" прямоугольный) или
`PANEL_240x240` (1.3" / 1.54" квадратный). Интерфейс сам перестраивается: на прямоугольном
Spinny и тахометр слева, а меню справа; на квадратном они сверху, а меню снизу.
Карточка редактирования и кнопка ПЕЧАТЬ на квадратном экране крупнее.

## Если экран странный

- Цвета как негатив: `TFT_INVERT 0`.
- Вверх ногами: другой `TFT_ROTATION` (170x320: 1 или 3; 240x240: 0, 1, 2, 3).
- Картинка съехала или полоса мусора: раскомментируй `TFT_OFFSET_X` / `TFT_OFFSET_Y` и подбери (0, 35 или 80).
- У квадратного модуля нет вывода CS: `PIN_TFT_CS -1` и `TFT_SPI_MODE 3`.
- Хочется ещё плавнее: `TFT_SPI_HZ 80000000` (при длинных проводах может глючить).

## Нагрузка на ESP32 и плавность

Интерфейс держит **ровные 60 кадров в секунду**: кадры идут по точной сетке в микросекундах,
и анимации считаются от времени кадра, а не от «когда получилось». Поэтому нет рывков от того,
что один кадр 16 мс, а другой 17. На 30 к/с экран переходит, только если всё полностью замерло
(никто не нажимает, Spinny спит или выключен). Если плата не успевает рисовать 60, она сама
переходит на ровные 30, а не дёргается между 60 и 30.

Что сделано, чтобы кадр был дешёвым:
- На ESP32-S3 `sqrtf`, `fminf`, `fmaxf` и деление — это вызовы библиотеки (около 100 тактов на
  корень). В рисовании их заменили на встроенные быстрые версии с точностью ~5·10⁻⁶.
- Фигуры рисуются «шагами по строке»: если пиксель далеко от края, сразу перескакиваем через
  несколько пикселей (пустые пропускаются, внутренние просто заливаются). Считаются только
  пиксели на краю, где нужно сглаживание.
- Тело Spinny рисуется как одна фигура, а не 14 отдельных кусков друг на друге: каждый пиксель
  считается один раз и только по 1–3 ближайшим кускам. Тонкие волоски жабр рисуются линиями.
- Свечение считается кольцами по строкам, без вычислений на каждый пиксель.
- Файл рисования компилируется с `-O2` (Arduino по умолчанию собирает `-Os`, для маленького кода).
- На экран уходит только то, что изменилось. Байты переставляются по пути в маленький буфер,
  поэтому следующий кадр можно рисовать, пока предыдущий ещё уходит по DMA.

**Сколько это стоит.** Замер в эмуляторе ESP32-S3 (QEMU от Espressif), считались команды
процессора на кадр:

| | v0.6 | v0.7 |
|---|---|---|
| меню, Spinny плавает | ~9,7 млн | ~1,7 млн |
| меню, листаем | ~11,9 млн | ~1,9 млн |

Примерно в 6 раз меньше работы. На настоящей плате при 240 МГц это ориентировочно 7–12 мс на
кадр (бюджет для 60 к/с — 16,7 мс). Эмулятор не считает такты точно, поэтому настоящее время
кадра смотри на своей плате: Сервис → О принтере (кадры в секунду, мс на кадр, КБ на кадр).

Мотор от экрана не зависит: шаги идут от аппаратного таймера.

## Spinny

Spinny — гибкая цепочка из 15 суставов: голова плывёт к цели, тело тянется следом. Поэтому
он изгибается, а разворачивается через себя, лицом к тебе (видно оба глаза). На скорости он
прижимает лапки, а когда стоит, гребёт ими. Жабры «дышат» и шевелятся.

- Плавает по своему уголку: то несколько гребков на месте, то разворот и через весь уголок.
  Тело всегда остаётся на экране.
- На прямоугольном экране держится рядом с выбранным пунктом и ныряет, когда листаешь.
- Если ничего не нажимать: иногда всплывает глотнуть воздуха, иногда ему насыпают корм. Он
  подплывает и глотает (открывает рот).
- Через минуту без нажатий медленно опускается ровно на дно и засыпает (zZz).
- «Готово!»: радостно носится туда-обратно. Ошибка: пугается и шарахается в сторону.
- Выключить или перекрасить: Сервис → Аксолотль.

## Протокол с Raspberry Pi (USB или провода TX/RX, 115200, строки текста)

| Pi → ESP | что делает |
|---|---|
| `PING` | ответ `PONG SpinScreen 0.7.2`; Pi шлёт раз в секунду, иначе экран пишет «нет Pi» |
| `RPM 9.5` | скорость вращения, об/мин |
| `SPIN 1` / `SPIN 0` | мотор вкл/выкл (с плавным разгоном) |
| `STATE PRINT` / `STATE DONE` / `STATE IDLE` / `STATE ERROR текст` | состояние печати |
| `PROG 42 80` | прогресс 42 %, осталось 80 секунд |
| `MSG текст` | Spinny скажет это в пузыре |
| `GET` | текущие настройки |
| `POS` | ответ `POS <угол°> <об/мин> <на скорости 0/1>`, отвечает за ~1 мс |
| `ZERO` | угол := 0 (ответ `ZEROED`) |
| `SETANGLE 12.5` | угол := 12.5° (Pi совмещает флакон с кадром видео в момент включения света) |
| `TURNS 6` · `WAIT 30 warm` · `DROPS 2` | сколько оборотов · ожидание до света (spin/warm/dark) · пропуски кадров |
| `URL http://…` / `HOST …` / `NET …` | адрес для QR-кода, имя хоста, Wi-Fi |
| `FILE имя.mp4` / `SYNC 12` | что печатается / ошибка синхронизации в мс (для экрана) |
| `FL BEGIN n поправка% пауза обороты` · `FL i rpm usb расчёт допуск сек/об кадры_ок имя` · `FL END` | список видео для экрана «Печать» |
| `CAL offset vial` | центровка и ширина флакона (для меню Проектор) |

| ESP → Pi | когда |
|---|---|
| `EV LIST` | открыли список видео |
| `EV PRINT i обороты поправка% пауза` | нажали ПЕЧАТЬ |
| `EV RESULT under/ok/over` | ответ на «Как получилось?» |
| `EV PATTERN name` · `EV OFFSET px` · `EV VIALW px` | Сервис → Проектор |
| `EV REBOOT` / `EV POWEROFF` | Сервис → Raspberry Pi |
| `EV STOP` | на экране печати долго держали OK |
| `EV SPIN 1/0`, `EV RPM 9.5` | поменяли мотор или скорость с экрана |
