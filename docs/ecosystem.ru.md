# Экосистема SpinSlicer + SpinPrinter

Черновик для обсуждения. Цель: от модели до готовой детали без ручной переписки цифр.
Слайсер знает про принтер всё, что нужно для расчёта, а принтер знает про каждое видео всё,
что нужно для печати.

## 1. Кто за что отвечает

| часть | где работает | что делает |
|---|---|---|
| **SpinSlicer** | ПК (Windows, Mac, Linux) | модель → проекции → видео одного оборота + расчёт дозы и числа оборотов; пакует всё в файл `.spin` и отправляет на принтер |
| **SpinPi** | Raspberry Pi | библиотека печатей (Wi-Fi и USB-флешки), веб-страница, профиль принтера, история печатей, ведёт печать |
| **SpinProj** | Raspberry Pi | на каждом vsync выводит на проектор кадр, который соответствует текущему углу флакона |
| **SpinScreen** | ESP32-S3 | экран 2.4" и джойстик, шаговый мотор с точным счётом шагов, отдаёт угол флакона |
| **Установщик** | браузер (Chrome/Edge) | прошивает ESP32 одной кнопкой |

## 2. Путь печати глазами пользователя

1. **Первый раз.** Прошить ESP через установщик. Записать карту для Pi одной командой.
   Принтер появляется в сети как `spinslicer.local`.
2. **Настройки → Принтер → «Подключить».** Слайсер находит принтер сам (mDNS) и забирает его профиль:
   разрешение и яркость проектора, диаметр флакона, калибровку центра. Что поменял в слайсере,
   можно «Записать в принтер» (`POST /api/printer`): источник правды остаётся на принтере.
3. **Нарезка.** Модель, смола, «Рассчитать». Слайсер показывает время печати и число оборотов.
4. **«Напечатать».** Файл `.spin` уходит на SpinPi по сети, следом `POST /api/print` с `"confirm": true`.
   Без сети: **«На флешку»**, слайсер сам находит съёмный диск.
5. **Подтверждение на принтере.** Экран спрашивает «Печатать?» (имя, обороты, время): флакон должен
   стоять. Джойстик вправо → печать, влево → отмена; без ответа вопрос снимается через 10 минут.
   Слайсер показывает «Подтвердите на экране принтера», потом ход печати и «Стоп».
6. **«Как получилось?»** Ответ (недосвет / норма / пересвет) уходит в историю. Слайсер видит историю
   и уточняет дозу этой смолы для следующей нарезки.

## 3. Формат `.spin` (версия 1)

Один файл на одну печать. Внутри обычный ZIP без сжатия (видео и так сжато), как `.3mf` в
FDM-печати: открывается любым архиватором, читается стандартными библиотеками.

```
part.spin
├── spin.json      метаданные (обязательный, лежит первым)
├── video.mp4      один оборот флакона, H.264 (обязательный)
├── preview.png    картинка детали 320×320 для экрана и веб-страницы (желательно)
└── slicer.json    все настройки нарезки, чтобы повторить её (необязательный)
```

### `spin.json`

```json
{
  "format": "spin",
  "version": 1,
  "created": "2026-11-07T21:40:00Z",
  "generator": "SpinSlicer 0.7.0",
  "name": "lattice_cube",

  "video": {
    "file": "video.mp4",
    "sha256": "…",
    "frames": 1200,
    "fps": 30,
    "width": 1280, "height": 800,
    "frames_per_rev": 1200,
    "rotation": "ccw_from_top",
    "frame0_angle_deg": 0.0
  },

  "plan": {
    "revolutions": 5.35,
    "tolerance_pct": 6.0,
    "revolution_s": 40.0,
    "print_time_s": 214.0,
    "rpm": 1.5,
    "warnings": []
  },

  "resin":   { "name": "Anycubic Clear", "alpha_per_mm": 0.08, "gel_dose_mj_cm3": 12.0 },
  "printer": { "profile_id": "spinslicer-3f2a", "vial_diameter_mm": 25.0,
               "projector": { "width": 1280, "height": 800, "irradiance_mw_cm2": 4.1 } }
}
```

Правила:
- `version` растёт только при несовместимых изменениях. Незнакомые поля читатель **игнорирует**,
  поэтому новые поля можно добавлять в любой момент.
- `video.rotation` и `frame0_angle_deg` описывают, как кадры привязаны к углу флакона. Принтер
  сверяет это со своим направлением мотора и, если они расходятся, показывает видео в обратном
  порядке, а не печатает брак.
- `printer.profile_id` — для какого принтера считалось. На другом принтере печать не запрещается,
  но экран предупреждает.
- `sha256` защищает от битой копии на флешке.

### Совместимость

SpinPi продолжает принимать обычные видео: `.mp4` + `<имя>.spin.json` рядом, JSON в теге MP4
`comment`, имена в стиле OpenCAL `деталь_9rpm.mp4`. `.spin` просто основной путь.

## 4. Сеть и API принтера

- **Обнаружение:** SpinPi объявляет в mDNS `_spinprinter._tcp` (avahi уже стоит) с полями
  `name`, `id`, `api=1`. Слайсер показывает список найденных принтеров. Можно ввести адрес руками.
- **API** (HTTP + JSON, всё уже частично есть в `spinpi.py`):

| запрос | что делает |
|---|---|
| `GET /api/printer` | профиль принтера (id, имя, проектор, флакон, калибровка, мотор, версии ПО); `POST` — изменить |
| `PUT /api/files/<имя>.spin` | загрузка `.spin` (и видео); битый файл → 400 `{"ok":false,"error":…}` |
| `GET /api/files` | библиотека: имя, превью (`/api/thumb`), расчёт, источник (Wi-Fi/USB), `reversed`, `other_printer`, `error` |
| `GET /api/history` | печати с расчётом, фактическими оборотами, поправкой, смолой и ответом «как получилось» |
| `GET /api/state`, `/api/events` | состояние и события печати |

Сделано в SpinPi 0.6.0 (поля ответов — в [SpinPi/README.md](../SpinPi/README.md#для-разработчиков-http-api)).
mDNS: `spinpi.py` сам пишет `/etc/avahi/services/spinprinter.service` (TXT `name`, `id`, `api=1`,
`path=/api/printer`).

## 5. Профиль принтера

Хранится на Pi (`settings.json`), правится на веб-странице, отдаётся слайсеру:
id, имя; проектор (разрешение, частота, облучённость на оси, контраст); флакон (диаметр, стенка,
показатель преломления); калибровка (смещение центра, ширина флакона в пикселях); мотор (передача,
направление). Слайсер при выборе принтера подставляет это в расчёт, руками ничего не вводится.

## 6. Синхронизация мотора и видео (как работает сейчас)

ESP считает каждый шаг мотора и знает угол флакона. SpinPi 20 раз в секунду спрашивает угол
(`POS`), SpinProj на каждом vsync выводит кадр, соответствующий этому углу. Кадры привязаны к углу,
а не ко времени, поэтому видео не может «уплыть». В начале печати SpinPi выставляет `SETANGLE`,
и свет гаснет ровно через N оборотов.

С `.spin` (SpinPi 0.6.0): `frames_per_rev` задаёт, сколько кадров разжать на оборот (видео может
быть длиннее); `frame0_angle_deg` уходит в SpinProj как `PHASE`; если `rotation` не совпадает с
направлением мотора из профиля, SpinPi шлёт SpinProj `REVERSE 1`, и кадры идут в обратном порядке.
В режиме `--engine mpv` такое видео не печатается (ошибка вместо брака), `SETANGLE` учитывает кадр 0.
Осталось проверить на железе: замерить ошибку синхронизации (`SYNC` в мс) на реальном моторе.

## 7. Обратная связь по смоле

После каждой печати ответ «как получилось?» уже двигает поправку экспозиции на принтере.
Новое: эта история (смола, расчётная доза, фактическая поправка, ответ) отдаётся через
`/api/history`, и слайсер предлагает уточнить `gel_dose` этой смолы. Чем больше печатей,
тем точнее расчёт.

## 8. Одно железо

Прошивка под один вариант (`SpinScreen_v0.7/SpinScreen/config.h`): ESP32-S3 Super Mini, экран
ST7789 2.4" 240×320 и джойстик KY-023 на проводах, TMC2209, с Pi только USB-кабель. Интерфейс
рисуется под 320×240. Настройки железа на плате, команда `CONFIG`, другие экраны, кнопки, крутилка,
раскладка «на макетке», провода UART к Pi и SpinOS убраны (2026-11-08), чтобы собирать принтер было
одним способом.

## 9. Порядок работ

| # | что | репо | зависит от |
|---|---|---|---|
| 1 | спецификация `.spin` v1 (этот документ, раздел 3) | SpinPrinter `docs/` | — |
| 2 | экспорт `.spin` + «Отправить на принтер» + выбор принтера по mDNS | SpinSlicer | 1 |
| 3 | приём `.spin`, `/api/printer`, `/api/history`, mDNS-сервис, превью на веб-странице | SpinPi | 1 |
| 4 | профиль принтера в слайсере (забирать с принтера) | SpinSlicer | 3 |
| 5 | «Печатать?» на экране принтера, `confirm` в `/api/print` | SpinScreen, SpinPi | 3 |
| 6 | слайсер: «Подключить», «Записать в принтер», «Напечатать», «На флешку» | SpinSlicer | 4, 5 |
| 7 | проверка синхронизации на железе | все | 3 |

2, 3 и 5 можно делать параллельно, как только согласован формат.

## 10. Открытые вопросы

- Видео в `.spin` всегда ровно один оборот или бывают длиннее (несколько оборотов разными кадрами)?
- Нужен ли в `.spin` сам STL, чтобы на принтере можно было показать 3D-превью?
- Поддерживать ли печать без Pi (ESP + проектор от ПК)? Сейчас всё рассчитано на Pi.
