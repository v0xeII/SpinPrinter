# План: принтер SpinCAL — сеть, флешка, экран, веб-интерфейс, калибровка

## Контекст

Сейчас слайсер умеет только три вещи: выводить кадры на второй монитор, сохранять MP4 и сохранять PNG.
- Мотором слайсер не управляет.
- Кадр выбирается по времени ([video_tab.py:369](spinslicer/video_tab.py:369)). Часы компьютера и мотора расходятся, и за 10 минут печати набегает ~2°.
- Когда у Hitachi пропадает сигнал, он показывает яркий синий экран и засвечивает смолу.

Прошивка OpenCAL проще:
- видео с флешки, обороты берутся из имени файла;
- мотор и видео запускаются вслепую, без синхронизации;
- символьный дисплей 20×4.

**Цель.** Принтер должен работать как Bambu:
- слайсер сам находит принтер в локальной сети и отправляет задание;
- задание можно принести на флешке;
- на принтере есть чёткий сенсорный экран с собственным интерфейсом;
- с телефона доступен веб-интерфейс;
- калибровка проходит пошагово, и её результаты сами подтягиваются в слайсер;
- печать идёт по реальному углу колбы, с заслонкой и защитной блокировкой.

**Решения пользователя:**
- железо: Raspberry Pi 3B+, ESP32 (разные), драйвер TMC2209;
- экран: плата ESP32-S3 с сенсорным экраном 5";
- прошивка принтера живёт в **отдельном репозитории**.

## Архитектура

```
 Слайсер (ПК) ──Wi-Fi/LAN: mDNS + HTTP + WebSocket──┐
 Телефон (браузер) ──────── то же API ──────────────┤
                                                    ▼
                                   Raspberry Pi 3B+ «мозг»
                                   ├─ HDMI → активный HDMI-VGA → Hitachi (кадры 1024×768@60)
                                   ├─ USB-флешка (импорт .spincal)
                                   ├─ USB-serial → ESP32 «мотор»: TMC2209 + серва-заслонка + датчик дверцы + кнопка СТОП
                                   └─ USB-serial → ESP32-S3 5" «панель»: интерфейс принтера (LVGL)
```

**Кто за что отвечает:**
- **Pi** — единственный источник истины: хранит задания, профиль принтера с калибровкой, ведёт печать по конечному автомату, держит API и раздаёт веб-интерфейс.
- **ESP32 «мотор»** — всё, что требует реального времени: шаги мотора, счётчик угла, заслонка, блокировки. Заслонку закрывает **сам**, без участия Pi: при открытой дверце, нажатой кнопке СТОП или если Pi не отвечает дольше 1 секунды.
- **ESP32-S3 «панель»** — просто ещё один клиент того же API, только по serial вместо HTTP. Логики печати в ней нет.

## Формат задания `.spincal` (v1)

Это zip-архив без сжатия, PNG и так сжаты. Одним файлом его удобно и слать по сети, и носить на флешке.

**Содержимое:**
- `job.json`:
  - `schema`: `"spincal-job/1"`, `job_id` (uuid), `name`, `created`, `slicer_version`;
  - `canvas`: `{width, height, offset_x, offset_y}` из `canvas_geometry()`;
  - `frames`: `{count, width, height, angles_deg, angle_direction, angle_offset_deg, sha256: [...]}`;
  - `motion`: `{deg_per_s}` из `ui/speed`;
  - `exposure`: `{duration_s, brightness, gamma, exposure_factor}`. `duration_s` берём из `print_duration_s()`;
  - `optics`: `{vial_diameter_mm, vial_px, bath, n_liquid}` — нужен для проверки, что задание считали под этот принтер;
  - `print_plan` — копия `print_plan.json`.
- `frames/frame_0000.png …` — 8-битные полосы как есть. Компоновку на холст и таблицу яркости Pi применяет сам.
- `preview.png`, 320 px — для списка заданий на панели и в вебе.
- `manifest.json` — копия манифеста запуска, для истории печатей.

Главный документ протокола будет лежать **в репозитории слайсера**: `docs/printer_protocol.md` и `docs/schemas/spincal-job-1.json`. Репозиторий принтера держит копию схемы и проверяет её общим тестовым файлом (`tests/data/sample.spincal`).

## Протоколы

### 1. Слайсер и телефон ↔ Pi (HTTP + WebSocket)

**Обнаружение:** mDNS через avahi, сервис `_spincal._tcp`, порт 8080. В TXT-записи: `name`, `api=1`, `model`, `fw`.

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/info` | Имя, версия API, разрешение проектора, состояние. Без токена. |
| GET | `/api/profile` | Профиль и калибровка принтера (см. ниже). |
| GET / POST / DELETE | `/api/jobs` | Список заданий (сеть + флешка), загрузка `.spincal` потоком с проверкой sha256, удаление. |
| POST | `/api/print` `{job_id}` | Запуск печати. |
| POST | `/api/stop` | Остановка: заслонка закрывается сразу. |
| POST | `/api/calib/<шаг>` | Показать тестовую картинку, сдвинуть, сохранить. |
| POST | `/api/motion/jog`, `/api/shutter` | Ручное управление. Запрещено во время печати. |
| WS | `/api/events` | Состояние ~2 раза в секунду: `state`, `progress`, `elapsed`, `remaining`, `deg_per_s` (измеренная), `door`, `shutter`, `faults`. |

**Доступ.** Всё, что что-то меняет, требует токен. Токен выдаётся после ввода 6-значного PIN, который принтер показывает на панели, как LAN-код у Bambu. Чтение `/api/info` открыто.

### 2. Pi ↔ ESP32 «мотор» (JSON по строкам, 921600 бод)

Тот же стиль, что у `engine_process.py`: один JSON-объект на строку.
- **Команды:** `hello`, `cfg {microsteps, steps_per_rev, current_ma, invert, shutter_open, shutter_closed}` (сохраняется в NVS), `spin {deg_per_s}`, `stop`, `jog {deg}`, `shutter {open|close}`, `ping`.
- **События:**
  - `pos {seq, t_us, steps}` с частотой 200 Гц;
  - `state`;
  - `fault {door|estop|watchdog|driver}`;
  - `button`.

### 3. Pi ↔ ESP32-S3 «панель» (JSON по строкам)

- Pi отправляет `state` (тот же объект, что в WebSocket), `jobs` и `profile`.
- Панель отправляет `action {name, args}`. Имена действий совпадают с методами API.

## Ход печати и безопасность (конечный автомат на Pi)

**Состояния:** `idle → loading → spinup → exposing → finishing → done`, плюс `error` и `aborted`.

1. **`loading`.** Проверить схему задания и sha256. Проверить, что `canvas` совпадает с разрешением проектора из профиля, а `optics` — с профилем; при расхождении предупредить. Затем разжать полосы в память и применить таблицу яркости. 720 полос × ~250 КБ ≈ 180 МБ, в 1 ГБ помещается.
2. **`spinup`.** Дверца закрыта, заслонка закрыта, на проекторе чёрное. Мотор разгоняется до `deg_per_s`. Ждём установившейся скорости и ещё один оборот.
3. **`exposing`.**
   - Запомнить `steps0` и открыть заслонку.
   - На каждом кадровом гасящем импульсе: угол = (steps − steps0) / шагов на оборот × 360. Угол предсказывается на момент показа по линейной модели «шаги ↔ время Pi».
   - Номер кадра = ⌊N · дробная_часть((угол·направление + смещение) / 360)⌋.
   - Время засветки считается, только пока заслонка открыта. Когда набралось `duration_s`, переходим к завершению.
4. **`finishing`.** Закрыть заслонку, вывести чёрное, остановить мотор. Записать в историю: фактические обороты, пропущенные кадры, время.

**Блокировки:**
- открытая дверца, кнопка СТОП, пропавшие пакеты `pos` или сбой драйвера → заслонка закрывается (ESP32 делает это сам), печать переходит в `aborted`;
- без активного задания на проектор всегда идёт чёрный кадр.

## Калибровка (пошаговые мастера на панели и в вебе)

Результаты хранятся в профиле принтера на Pi: `/var/lib/spincal/printer.json`. По структуре он совпадает с `profiles.MachineProfile` ([profiles.py:124](spinslicer/profiles.py:124)) плюс поля оптики.

1. **Картинка 1:1.** Сетка с шагом 1 px и шахматка. Проверяем, что проектор не масштабирует, и что режим 1024×768@60 включился.
2. **Колба.** Разметка `alignment_pattern` ([video_tab.py:47](spinslicer/video_tab.py:47)). Кнопками ± подгоняем `vial_px`, `offset_x`, `offset_y` и видим результат сразу.
3. **Линза (телецентричность).** Выводим рамку, пользователь вводит её ширину W1 и W2 в двух положениях листа на расстоянии L. Расчёт: Δ = f² · (W2 − W1) / (W · L). Мастер говорит, на сколько миллиметров и куда сдвинуть линзу.
4. **Фокус.** Тонкие линии и звёздочка. Фокусируем на оси колбы.
5. **Мотор.** Поворот на +90°: пользователь подтверждает направление, сохраняется `angle_direction`. Затем проверка скорости: сравниваем заданные обороты с измеренными по шагам.
6. **Заслонка.** Подбор углов сервы «открыто» и «закрыто» с живым предпросмотром.
7. **Гамма.** Шкала серого `calibration_ramp` ([workers.py:302](spinslicer/workers.py:302)), значение вводится вручную.
8. **Доза.** Существующая «шкала» слайсера ([calibration.py](spinslicer/calibration.py), [calibration_dialog.py](spinslicer/calibration_dialog.py)) отправляется на принтер, результат вводится в слайсер как сейчас.

В слайсере появится кнопка **«Взять настройки с принтера»**. Она заполнит разрешение, «Колба на экране», сдвиги, гамму, контраст и частоту из `/api/profile`. Это главный выигрыш интеграции: калибровка делается один раз на принтере, и слайсер всегда считает под него.

## Порядок работ (вехи)

1. **M0. Проверка рисков на железе.**
   - Pi 3B+ через HDMI-VGA выдаёт 1024×768@60.
   - pygame kmsdrm пропускает меньше 0,1% кадровых импульсов при смене полосы на каждом из них.
   - ESP32 отдаёт `pos` 200 Гц, дрейф за 30 минут ≈ 0.
   - Если kmsdrm не тянет, переходим на прямой вывод через DRM (pykms).
2. **M1. Слайсер:** `.spincal`, «на флешку», документ протокола и схема.
3. **M2. Pi:** чтение заданий, флешка, плеер по углу, связь с ESP32, конечный автомат. Запускается из командной строки.
4. **M3. Прошивка «мотор»:** шаги, угол, заслонка, блокировки, сторожевой таймер.
5. **M4. Pi:** HTTP API, mDNS, веб-интерфейс, PIN и токен.
6. **M5. Слайсер:** поиск принтеров, отправка, состояние, стоп, «взять настройки с принтера».
7. **M6. Прошивка «панель»** на ESP32-S3.
8. **M7.** Мастера калибровки целиком, история печатей.

M1 и M2/M3 не зависят друг друга. M5 зависит от M4, M6 — от M2.

  - вручную: сохранить `.spincal`, открыть его `read_job`, отправить на поддельный сервер.

  - прогон всего автомата с `FakeMotion` и `FakePlayer` на ПК без железа;
  - тест совместимости на `sample.spincal` из слайсера.
- **Прошивки:** `pio run` для обеих (компиляция). Проверку на железе по чек-листу делает пользователь.
- **Железо, по шагам:**
  1. чёрный экран и закрытая заслонка при пропаже сигнала;
  2. открытие дверцы закрывает заслонку менее чем за 100 мс;
  3. 30 минут вращения без ухода угла;
  4. сухой прогон с колбой воды;
  5. печать шкалы дозы на смоле.
