# SpinProj: проектор показывает кадр по углу флакона

**Русский** · [English](README.en.md)

Маленькая программа на C. На каждом кадровом импульсе проектора (vsync) она выводит тот кадр,
который соответствует текущему углу флакона. Угол считает ESP32 по шагам мотора, SpinPi
пересылает его 20 раз в секунду.

```
ESP32 (шаги мотора) ──USB──► SpinPi ──«A угол об/мин время»──► SpinProj ──HDMI──► проектор
```

Чем это лучше, чем крутить видео (OpenCAL, SpinPi 0.4 с mpv):
- видео не может «уплыть» от мотора: кадр выбирается по углу, а не по времени;
- пропущенный vsync ничего не сдвигает: на следующем снова нужный кадр;
- свет гаснет ровно через N оборотов, с точностью до одного обновления экрана;
- если угол перестал приходить на 0,3 с, свет гаснет сам. Если упал SpinPi, тоже гаснет.

Перед печатью один оборот кадров разжимается в память: 8-битный серый, сжатый LZ4.
Подходит любой файл, который читает ffmpeg: MP4 (и от OpenCAL), MKV без потерь (FFV1),
последовательность PNG.

## Выводы

| `--out` | где | для чего |
|---|---|---|
| `drm` | проектор на Pi (DRM/KMS, page flip) | печать |
| `sdl` | окно на компьютере | посмотреть на ПК |
| `null` | никуда, точные «60 Гц» | автотесты |

## Собрать

```bash
make                 # находит SDL2 и libdrm сам; без них собирается только null
make NO_SDL=1        # на Pi
```
Нужно: gcc, make, liblz4 (на Pi OS: `sudo apt install liblz4-dev libdrm-dev`).

## Замер на Pi 3B (шаг 1 плана)

Служба SpinPi должна быть остановлена, проектор или монитор подключён по HDMI:
```bash
sudo spinproj bench --rt --cpu 3                       # синтетические кадры, похожие на CAL
sudo spinproj bench --rt --cpu 3 --video печать.mp4    # твоё настоящее видео
```
Покажет: сколько памяти займёт оборот, сколько таких кадров влезет в RAM, сколько миллисекунд
уходит на распаковку кадра, насколько ровные vsync и сколько пропущено. Последняя строка
`RESULT …` пригодится, чтобы прислать цифры целиком.

**Цифры с компьютера для Pi ничего не значат.** На компьютере, где это писалось, кадр 1280×800
готовится за 1,5–3 мс, а на Pi 3B будет медленнее во сколько-то раз. Насколько, покажет только замер.

## Команды (stdin → SpinProj)

| команда | что делает |
|---|---|
| `LOAD <кадров на оборот> <файл>` | разжать оборот в память (в фоне) |
| `A <угол°> <об/мин> <время нс> [время ответа нс]` | угол от ESP32; время по `CLOCK_MONOTONIC` (как `time.monotonic_ns()` в Python); медленным ответам фильтр доверяет меньше |
| `ARM <обороты>` | со следующего vsync свет ровно на столько оборотов |
| `STOP` / `BLACK` | погасить |
| `IMAGE <файл.pgm>` | тестовая картинка (сетка, центровка…) |
| `OFFSET <px>` | сдвиг картинки вбок (центровка по оси вращения) |
| `PHASE <°>` | какой угол показывает кадр 0 (по умолчанию 0) |
| `PING` / `QUIT` | |

| ответ (stdout) | когда |
|---|---|
| `READY <вывод> <ширина> <высота> <Гц>` | запустился |
| `LOADING i n` · `LOADED n w h МБ_сырые МБ_LZ4 секунды` | разжимает / готово |
| `LIGHT <угол>` | свет включён |
| `STAT <градусов пройдено> <кадров> <пропущено vsync> <макс мс на кадр> <разброс угла мс>` | 2 раза в секунду при свете |
| `DONE <кадров> <пропущено> <мин> <макс> <среднее> <макс мс>` | N оборотов прошли; мин/макс/среднее = сколько обновлений экрана показан каждый кадр |
| `STOPPED` · `ERR текст` · `INFO текст` | |

## Про ровность дозы

Каждый кадр стоит на экране целое число обновлений. Если обновлений на кадр не целое число
(видео 24 к/с при 60 Гц = 2,5), кадры по очереди стоят 2 и 3 обновления. Так же и у обычного
видеоплеера. SpinPi об этом предупреждает. Ровно будет при 30 или 60 к/с на 60 Гц.
